# Native builds (Tauri v2): desktop, Android and iOS

> **Navigation aid.** `path:line` references mean "near here"; refresh them when you touch the code.
> Everything on this page was verified on real targets on 2026-09-18: a packaged macOS app, and an
> Android debug APK on a Pixel 8 (Android 17, WebView 151). The iOS section comes from a spike
> against tauri-cli 2.12.1 on 2026-10-09.

## Purpose

Package a Caper game as a native app. [Tauri v2](https://v2.tauri.app) wraps the app's ordinary
`vite build` output (`dist/`) in the platform's system webview: WKWebView on macOS/iOS, WebView2 on
Windows, WebKitGTK on Linux, the Chromium System WebView on Android. Nothing about the game changes;
no custom Rust is needed. The game still runs at the speed of that webview.

## The pieces

| Piece | Where | What it does |
| --- | --- | --- |
| Preset awareness | `packages/core/build/defaults.mjs` (`tauriDefaults`), `build/index.mjs` | When the Tauri CLI runs Vite (`TAURI_ENV_PLATFORM` is set): no browser tab, `strictPort`, `TAURI_DEV_HOST` for device HMR, `src-tauri/**` unwatched, PWA plugin skipped (service workers cannot register on `tauri://`). The project's own `vite.config` still wins. See [build-pipeline.md](build-pipeline.md#native-tauri). |
| `isTauri` | `packages/core/src/utils/platform.ts` | `true` inside a Tauri webview. SSR-safe. |
| `caper native init` | `packages/core/cli/native.mjs` | Scaffolds `src-tauri/` (`tauri init --ci`), sets a real identifier, a per-app dev port (3100-3999, never 3000), a 1280x720 window (450x800 when `caper.config.ts` sets `orientation: 'portrait'`), and `native:dev` / `native:build` scripts. `beforeBuildCommand` is a bare `vite build` on purpose (see Gotchas). See [cli-and-package.md](cli-and-package.md). |
| `caper native plugin` | same file | Idempotent. Adds `@caperjs/plugin-tauri` + `@tauri-apps/api`, runs `tauri add store`, grants `core:window:allow-set-fullscreen`, `allow-is-fullscreen`, `allow-close`. |
| `caper native android` | same file (`androidNative`) | Idempotent. Runs every Android step below: adds the Rust targets, runs `tauri android init --ci`, adds the 16 KB link arg to `build.rs`, hides the system bars in `MainActivity.kt`, locks the MainActivity to `caper.config.ts`'s `orientation` in `AndroidManifest.xml`, adds `native:android:dev` / `native:android:build` scripts. Finds the Android SDK, NDK, JDK and rustup on its own and passes them to every child process. `caper native android dev` / `build [...tauri args]` run `tauri android dev` / `build` with that same env (they need `src-tauri/gen/android/`). |
| `caper native ios` | same file (`iosNative`) | Idempotent, macOS only. Runs every iOS step below: checks for full Xcode, installs CocoaPods and XcodeGen with Homebrew when missing, adds the Rust targets, runs `tauri ios init --ci`, writes `src-tauri/Info.ios.plist` (status bar hidden, `caper.config.ts`'s orientation lock), sets the signing team with `--team <ID>`, adds `native:ios:dev` / `native:ios:build` and `tauri` scripts. `caper native ios dev` / `build [...tauri args]` run `tauri ios dev` / `build` with the same env (they need `src-tauri/gen/apple/`). |
| `caper doctor` rows | `packages/core/cli/doctor.mjs` | Only when `src-tauri/` exists: `rustc` >= 1.88, `@tauri-apps/cli` v2, identifier not a placeholder, dev port sane, Xcode CLT (macOS), plugin wiring. Once `src-tauri/gen/android/` exists, six more: the four Rust targets, `NDK_HOME`, `JAVA_HOME` (warn with an `export` hint when unset but found), 16 KB alignment in `build.rs`, hidden system bars in `MainActivity.kt`, and the manifest orientation matching `caper.config.ts`. On macOS, once `src-tauri/gen/apple/` exists, six iOS rows (see "iOS"). |
| `@caperjs/plugin-tauri` | `packages/plugin-tauri` | Runtime plugin, id `tauri`; inert on the web. Pause on hide (only resumes what it paused), native window fullscreen on desktop through `FullScreenPlugin.setFullscreenDriver` ([plugins-catalog.md](plugins-catalog.md)), durable saves (`app.store` adapter id `tauri`, a real file via `@tauri-apps/plugin-store`, `localStorage` fallback off-Tauri), `quit()`, context-menu suppression, Android back button as a key. Tauri packages are imported dynamically behind `isTauri`. |

Reference implementation: `apps/kitchen-sink/src-tauri/` (generated by `caper native init` +
`caper native plugin`, then the Android steps below, done by hand before `caper native android` existed).

## Desktop

```sh
caper native init        # once
caper native plugin      # once, optional but recommended
pnpm native:dev          # Tauri window on the Vite dev server
pnpm native:build        # installer / .app
```

Needs Rust >= 1.88 plus the platform toolchain (Xcode CLT, MSVC + WebView2, or the WebKitGTK dev
packages). Desktop targets cannot be cross-compiled; use CI (`tauri-action`) for the ones you are not on.

## Android

```sh
caper native android                                          # once; safe to re-run
pnpm native:android:dev                                       # on a device or emulator
pnpm native:android:build --debug --apk --target aarch64
adb install -r src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk
```

Prerequisites: Android Studio (SDK, an NDK, its bundled JBR), and Rust installed through **rustup**
(Homebrew's `rust` cannot add targets). The command stops with a plain-English list if the NDK, a JDK
or rustup cannot be found. The `native:android:*` scripts route through caper
(`caper native android dev|build`, `runAndroidTauri`): they resolve `NDK_HOME`, `JAVA_HOME` and a
rustup-first `PATH` themselves, then run `tauri android <dev|build>` with every other argument passed
through, so your shell needs no exports. To run `tauri android` directly instead, export the values the
setup command prints (and put rustup's bin ahead of Homebrew's `/opt/homebrew/bin` on `PATH`).

**What it does** (`androidNative` in `packages/core/cli/native.mjs`), and how to do it by hand:

- **Finds the toolchain** (`resolveAndroidEnv`). `ANDROID_HOME` (or `ANDROID_SDK_ROOT`, or
  `~/Library/Android/sdk` on macOS), `NDK_HOME` (or the highest version under `$ANDROID_HOME/ndk/`),
  `JAVA_HOME` (or Android Studio's bundled JBR on macOS). If `rustup` is not on `PATH`, or Homebrew's
  `rustc` comes before rustup's, it puts `/opt/homebrew/opt/rustup/bin` (keg-only Homebrew rustup,
  macOS) or `~/.cargo/bin` first. Nothing in your shell profile changes.
- **Adds the Rust targets** that are missing:
  ```sh
  rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
  ```
- **Generates the Android project** if `src-tauri/gen/android/` does not exist:
  ```sh
  export NDK_HOME="$ANDROID_HOME/ndk/<version>"
  export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"   # macOS
  pnpm tauri android init --ci
  ```
- **Makes the two edits below** (16 KB alignment, hidden system bars). It only replaces a file that is
  still Tauri's stock version. A file you changed is left alone, with a warning to make the edit by hand.
- **Locks the orientation** when `caper.config.ts` sets `orientation`. It sets
  `android:screenOrientation` on the `.MainActivity` element of
  `src-tauri/gen/android/app/src/main/AndroidManifest.xml`: `portrait` stays `portrait`, `landscape`
  becomes `sensorLandscape` (either landscape side, following the sensor). Change the config and
  run the command again to apply a new value. With `orientation` unset the manifest is left
  alone. Do not edit the attribute by hand; `caper doctor` warns when the two disagree. Either
  form works, `orientation: 'portrait'` or `orientation: { lock: 'portrait', overlay: ... }`; the
  config is read with an AST parse, so write the lock as a string literal. If it cannot be read,
  the command warns and skips this step.
- **Web versus native.** In a mobile browser the same `orientation` shows Caper's "rotate your
  device" overlay (`OrientationPlugin`, styled by `orientation.overlay`); inside Tauri that plugin stays off and the native
  app relies on this manifest lock instead.
- **Adds scripts** `native:android:dev` (`caper native android dev`) and `native:android:build`
  (`caper native android build`) to `package.json`. The old bare values (`tauri android dev` /
  `tauri android build`) are upgraded; any other value is left alone.

`src-tauri/gen/android/` is an Android Studio project and is meant to be committed (its own
`.gitignore` excludes build output). Three edits every Caper game needs; `caper native android`
makes the first two:

1. **16 KB page alignment** in `src-tauri/build.rs`. Android 15+ warns "not 16 KB compatible" and
   Google Play requires it. NDK r27 and older link with 4 KB alignment.
   ```rust
   fn main() {
       if std::env::var("CARGO_CFG_TARGET_OS").as_deref() == Ok("android") {
           println!("cargo:rustc-link-arg=-Wl,-z,max-page-size=16384");
       }
       tauri_build::build()
   }
   ```
   Check the result, do not assume it: `llvm-readelf -lW lib/arm64-v8a/libapp_lib.so` must show
   `LOAD` alignment `0x4000`, and `zipalign -c -P 16 -v 4 app.apk` must pass.
2. **Hide the system bars** in `gen/android/app/src/main/java/<id>/MainActivity.kt`. Tauri's template
   calls `enableEdgeToEdge()`, which draws the game underneath the status and navigation bars. Hide
   `WindowInsetsCompat.Type.systemBars()` with `BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE` in `onCreate`
   and again in `onWindowFocusChanged` (Android restores them on refocus). kitchen-sink's file is the
   template. `ResizerPlugin`'s safe-area handling then still accounts for the camera cutout.
3. **Bind the back button.** With `@caperjs/plugin-tauri`, a back press or gesture arrives as the key
   `GoBack` (option `backButtonKey`), and never closes the app by itself. Bind it like any key and let
   action contexts route it:
   ```ts
   keyboard: { up: { toggle_pause: ['P', 'GoBack'], close: ['Escape', 'GoBack'] } }
   ```
   `GoBack` and `BrowserBack` are members of `KeyboardKey` (`packages/core/src/utils/types.ts`).

## iOS

```sh
caper native ios                       # once; safe to re-run (macOS only)
caper native ios --team ABCDE12345     # add your signing team, needed for a device
pnpm native:ios:dev                    # pick a Simulator, or a device once a team is set
pnpm native:ios:build
```

Prerequisites: macOS, the full **Xcode** app selected with `xcode-select` (the Command Line Tools
alone are not enough), Rust installed through **rustup**, and Homebrew (for CocoaPods and XcodeGen).
`caper native ios` stops with a plain-English fix when Xcode or rustup is missing. The
`native:ios:*` scripts route through caper (`caper native ios dev|build`, `runIosTauri`): they set a
rustup-first `PATH` that also reaches `pod` and `xcodegen`, then run `tauri ios <dev|build>` with
every other argument passed through.

**What it does** (`iosNative` in `packages/core/cli/native.mjs`), and how to do it by hand:

- **Checks Xcode.** `xcode-select -p` must point inside an Xcode app, not
  `/Library/Developer/CommandLineTools`. Fix: `sudo xcode-select -s /Applications/Xcode.app`.
- **Installs CocoaPods and XcodeGen** with `brew install cocoapods xcodegen` (only the missing ones).
  Do this up front: without CocoaPods, `tauri ios init` tries `gem install cocoapods`, which needs
  sudo, fails, and still exits 0 without creating anything. `caper native ios` checks that
  `src-tauri/gen/apple/` exists afterwards and stops if it does not.
- **Adds the Rust targets** with rustup (`resolveIosEnv` finds it the same way as for Android):
  ```sh
  rustup target add aarch64-apple-ios aarch64-apple-ios-sim x86_64-apple-ios
  ```
- **Generates the Xcode project** if `src-tauri/gen/apple/` does not exist: `pnpm tauri ios init --ci`.
  Tauri writes the Rust build step into `gen/apple/project.yml` as `<runner> tauri ios xcode-script`.
  It picks `pnpm tauri` only when `npm_config_user_agent` starts with `pnpm/`, so caper sets that
  variable for pnpm apps; otherwise it writes `node tauri`, which fails inside Xcode (caper warns).
  npm apps get `npm run -- tauri`, which needs the `tauri` script caper adds to `package.json`.
- **Writes `src-tauri/Info.ios.plist`** (see below).
- **Sets the signing team** when you pass `--team <ID>`: `bundle.iOS.developmentTeam` in
  `src-tauri/tauri.conf.json`. A Team ID is 10 uppercase letters or digits.
- **Adds scripts** `native:ios:dev` (`caper native ios dev`), `native:ios:build`
  (`caper native ios build`) and `tauri` (`tauri`) to `package.json`. Old bare values
  (`tauri ios dev` / `tauri ios build`) are upgraded; any other value is left alone.

**`Info.ios.plist` is caper's file.** On every `tauri ios dev|build`, Tauri rebuilds
`gen/apple/app_iOS/Info.plist` from the generated plist, then `src-tauri/Info.plist`, then
`src-tauri/Info.ios.plist`, then `bundle.iOS.infoPlist`. Each one replaces whole top-level keys
(arrays are replaced, not merged). So caper's keys live in `src-tauri/Info.ios.plist`, never in
`gen/apple/` (XcodeGen only runs on init). The file starts with a marker comment: while it is there,
re-running `caper native ios` rewrites the file to match `caper.config.ts`. Delete the marker line to
keep your own edits; caper then leaves the file alone and warns. It sets:

| Key | Value | Why |
| --- | --- | --- |
| `UIStatusBarHidden` | `true` | Games own the whole screen. |
| `UIViewControllerBasedStatusBarAppearance` | `false` | Without it iOS ignores `UIStatusBarHidden`. |
| `UISupportedInterfaceOrientations` | portrait: `Portrait`; landscape: `LandscapeLeft`, `LandscapeRight` | Only when `caper.config.ts` sets `orientation`. iPhone lock. |
| `UISupportedInterfaceOrientations~ipad` | portrait: `Portrait`, `PortraitUpsideDown`; landscape: same as iPhone | iPad lock. |
| `UIRequiresFullScreen` | `true` | iPad only honours an orientation lock (and App Store validation only passes it) with this set. iPadOS 26 deprecates it, so expect this to change. |

**Signing: Simulator vs device.** Tauri reads the team from `APPLE_DEVELOPMENT_TEAM` first, then
`bundle.iOS.developmentTeam`. The Simulator needs no team; a real device does. Find your Team ID at
developer.apple.com > Account > Membership, then run `caper native ios --team <ID>`. Without one,
`caper native ios` warns and `caper doctor` shows `native-ios-team` as a warning.

**Safe area.** Caper's Vite preset already injects `viewport-fit=cover`, so the game draws under the
notch and `ResizerPlugin`'s safe-area handling applies. Measured on an iPhone 18 Pro Simulator (iOS 27,
portrait): 62 CSS px top (the Dynamic Island, even with the status bar hidden) and 34 px bottom (the
home indicator). See the gotcha below for using the top strip.

**Known limit: the home indicator** (the bar at the bottom of Face ID iPhones) stays visible. Hiding
it needs Rust/Objective-C in the app's `setup` hook (`prefersHomeIndicatorAutoHidden` on the root view
controller), which caper does not write.

**`caper doctor` rows** (macOS, once `src-tauri/gen/apple/` exists):

| Row | Checks |
| --- | --- |
| `native-ios-xcode` | Full Xcode is selected; fails with the `xcode-select -s` fix. |
| `native-ios-rust` | rustup and the three iOS targets; warns when Homebrew's `rustc` comes first on `PATH`. |
| `native-ios-tools` | `pod` and `xcodegen` are found (on `PATH` or in `/opt/homebrew/bin`). |
| `native-ios-team` | A team in `APPLE_DEVELOPMENT_TEAM` or `tauri.conf.json`; warns without one (fine for the Simulator). |
| `native-ios-plist` | `Info.ios.plist` hides the status bar. |
| `native-ios-orientation` | `Info.ios.plist`'s iPhone lock matches `caper.config.ts`; ok when neither sets one. |

**Interface** (`packages/core/cli/native.mjs`): `iosNative(cwd, { team }, deps)`,
`runIosTauri(cwd, mode, args, deps)`, `resolveIosEnv({ env, platform, homedir, exists, pm })`,
`isFullXcode`, `IOS_RUST_TARGETS`, `IOS_ORIENTATIONS`, `renderInfoIosPlist` / `planInfoIosPlist` /
`readPlistOrientation`, `patchIosTeam` / `isValidTeamId`, `patchIosScripts`, `xcodeScriptRunner`.

## Invariants & gotchas

- **A webview nobody can see runs nothing.** A hidden, occluded, or minimized desktop window, and an
  Android app behind the lock screen, stop timers and `requestAnimationFrame` entirely: a game started
  that way never reaches `Caper.ready()`, and any benchmark taken then is meaningless (a locked Pixel
  measured 30x slower). Tauri's `backgroundThrottling: "disabled"` revives timers but not rAF. Launch
  test builds in the foreground (`open` on macOS; check `adb shell dumpsys window | grep mCurrentFocus`).
- **No HTML Fullscreen API in the desktop webview** (WKWebView: `requestFullscreen` is undefined), so
  `app.fullScreen` only works there through the plugin's native driver. On Android it is the reverse:
  the DOM API works and Tauri's `setFullscreen()` rejects, so the plugin installs no driver on mobile.
- **A missing file comes back as `index.html` with status 200.** A bad asset path shows up as "cannot
  decode image/audio". The tell: the response is exactly `index.html`'s byte length.
- **A native build must never clean Vite's `cacheDir`.** kitchen-sink's old `build` script ran
  `rimraf ... .cache` and 504'd every pre-bundled dependency of a dev server running from the same
  folder. Hence `beforeBuildCommand: vite build`; apps with extra build steps edit it in
  `src-tauri/tauri.conf.json`.
- **`rustflags` in `src-tauri/.cargo/config.toml` have no effect** under the Tauri CLI (it drives
  cargo with its own `RUSTFLAGS`, which replace config rustflags). Use `build.rs` link args.
- **The macOS title bar takes the page's background colour** (seen on macOS 27): a light `body`
  background (a loading colour, say) shows as a strip above the game. Set the window's
  `"titleBarStyle": "Transparent"`, `"backgroundColor"` to the game's edge colour, and `"theme": "Dark"`
  so the title stays readable, in `src-tauri/tauri.conf.json`.
- **Android reports the camera hole as a top safe-area strip** even with the status bar hidden (51 CSS px
  on a Pixel 8), so a `UICanvas` pads its top row below it. Corner UI clears a centred punch hole; to
  use the strip, pass `useSafeArea: isTauri && isAndroid ? { top: false } : true`. The webview cannot
  tell a centred hole from a corner one.
- **iPhone reports the Dynamic Island as a top safe-area strip** the same way (62 CSS px on an iPhone 18
  Pro), plus 34 px at the bottom for the home indicator. The Android trick works here too:
  `useSafeArea: isTauri && (isAndroid || isIos) ? { top: false } : true`. Keep the bottom inset so
  buttons stay clear of the home indicator's swipe area.
- **Commit `src-tauri/gen/android/gradle/wrapper/gradle-wrapper.jar`.** Without it a fresh clone fails at
  the Gradle step ("Unable to access jarfile ... gradle-wrapper.jar"). A `*.jar` line in `.gitignore` hides it;
  `caper native android` adds a `!` exception for this one file when git ignores it.
- **Bundled assets get no HTTP range responses** (a `Range` request returns 200 with the whole file).
  Fine for WebAudio decode; matters for streamed `<audio>`/video.
- **`libc` 0.2.190 breaks iOS builds** (October 2026): `num_threads` 0.1.7, pulled in by Tauri through
  `time`, fails with "cannot find function `mach_task_self` in crate `libc`". Pin the last good version in
  `src-tauri/`: `cargo update -p libc --precise 0.2.189`. Drop the pin once a fixed `libc` or `num_threads`
  ships.
- **CSP:** ship `csp: null` (Tauri's default). Strict CSP needs `import 'pixi.js/unsafe-eval'`
  (fixed upstream in Pixi 8.20.1) and `worker-src 'self' blob:` for Pixi's texture worker and Caper's
  `TimerPlugin`; untested end to end.
- **Linux (WebKitGTK) is best effort**: GPU/driver-dependent WebGL. Tauri v3's Chromium (CEF) runtime
  is the likely answer; it was alpha in September 2026.
- **"Slow or broken in the native app" has so far never been Tauri.** The packaged app runs the
  production bundle in a 1280x720 window, which is simply a harsher test than a dev server in a tall
  browser tab. Reproduce in plain Chromium with the production bundle and a small window first.

## Size

Measured 2026-09-24 on kitchen-sink (`dist/` is 9.2 MB), arm64 only (`--target aarch64`):

| Build | Size | Notes |
| --- | --- | --- |
| Debug APK | 148 MB | `libapp_lib.so` alone is 134 MB (unoptimized, debug info). Never ship it. |
| Release APK | 19 MB | `pnpm native:android:build --apk --target aarch64`. Unsigned. `libapp_lib.so` is 15.6 MB. |
| Release AAB | 12.5 MB | add `--aab`. What Google Play takes; Play then serves per-device APKs. |

Tauri embeds the whole `dist/` inside `libapp_lib.so` (compressed), so there is no `assets/` folder in
the APK: game size shows up as native-library size. The release APK still passes both 16 KB checks.
